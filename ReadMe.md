#　CG2評価課題3

1. 3Dオブジェクト / スプライト表示と ImGui による Dynamic SRT 操作
3D OBJモデルの頂点・インデックス描画に加え、2D正射影行列を用いたスプライト表示を実装しています。ImGuiを統合し、モデルやスプライトの位置（Translate）・回転（Rotate）・拡大縮小（Scale）をリアルタイムに変更できるようにしました。  
静止画では伝わりにくい3D空間での変換処理や描画結果を、スライダー操作によって直感的に確認・実演できるようにしています。

2. 数学的に生成された 3D 幾何形状（球: Sphere）の描画
極座標系（緯度・経度分割）に基づき、頂点位置・法線ベクトル・UV座標をアルゴリズムによって自動生成する球体（Sphere）の動的描画を実装しました。
頂点データを持たない形状がコード上で構築されるプロセスを視覚化し、メッシュ分割数やマテリアル適用の変化をすぐに画面上で確認できるように構成しています。

3. ライティング方式の切り替え（Lambertian Reflectance / Half Lambert）
ピクセルシェーダー内で法線ベクトルと光線ベクトルの内積（N . L）を用いた標準的な Lambert 拡散反射モデルに加え、陰影の落ち込みを緩和して質感を保つ Half Lambert モデルを実装しました。
ImGuiのドロップダウンメニューから「None / Lambert / Half Lambert」をシームレスに切り替えられるようにしました。ライティングの違いによる非受光面の陰影表現の差を、評価者がその場で一目瞭然に比較できるようにしています。  

4. UV Transform（テクスチャ行列変換）
テクスチャ座標（UV）に対して 3 x 3（ 4 x 4 同次座標）の行列乗算を行うことで、テクスチャのスケーリング・回転・平行移動を実現しました。
ImGui上でUVの拡大率・回転角・シフト量を操作可能にし、アニメーションやタイリング処理の効果をビジュアルで即座に伝えられる設計にしています。

5. 多彩な標準3Dモデルの描画対応（Utah Teapot / Stanford Bunny / Suzanne / 独自モデル）
グラフィックス分野で標準的に用いられる複雑な形状モデル（Utah Teapot, Stanford Bunny, Suzanne など）をOBJローダー経由で正確に読み込み、描画するパイプラインを構築しました。
モデルごとに独立したトランスフォーム調整機能を設けることで、複雑なメッシュに対するライティングやシェーディングの乗り具合を多角的に提示できるようにしています。

6. MultiMesh ＆ MultiMaterial 対応
1つのOBJ/MTLファイル内に複数のメッシュやマテリアルが含まれる構造（usemtl / g / o タグ）を解析し、サブメッシュごとに適切なバッファ・テクスチャ・定数バッファを割り当てて描画する機能を実装しました。
複雑な複合オブジェクトも適切に分解・描画されることをUI上のツリー構造（TreeNode）で可視化し、各サブメッシュの可視状態（Visible）やマテリアルを個別調整して確認できるようにしました。

7. 入力および音響システム（XInput / DirectInput & XAudio2 Sound）
XInput/DirectInput によるゲームパッドおよびキーボード入力（DebugCamera操作含む）の対応、ならびに XAudio2 を用いたWAV音声の読み込み・再生機能を搭載しました。
視覚的なグラフィックスだけでなく、操作感（デバッグカメラやパッド移動）と聴覚的フィードバック（Sound再生）を統合することで、インタラクティブなアプリケーションとしての完成度をわかりやすく伝えています。

8. ゲームパッド入力システム（XInput）
ゲーム開発において直感的かつ安定した操作環境を提供するため、XInputAPIを利用したゲームパッド入力管理クラス（DirectInput）を実装しました。

デッドゾーン処理による誤入力防止:
アナログスティック入力（GetLeftStick / GetRightStick）において、傾き値が XINPUT_GAMEPAD_LEFT_THUMB_DEADZONE（標準しきい値）以下の微小な入力値を無効化（0にリセット）しています。これにより、コントローラーの個体差や経年劣化によるスティックの「ドリフト現象」を防ぎ、プレイヤーが意図しない挙動を起こさない安全設計としています。  入力を正規化して扱いやすく統一:
-32768 ～ 32767 の整数値で取得されるスティック座標および 0 ～ 255 のトリガー値を、-1.0f ～ 1.0f または 0.0f ～ 1.0f の float 型データへと正規化して返却しています。これにより、利用側のゲームロジック（main.cppなど）で計算がしやすく、拡張性の高いインターフェースを提供しています。  状態保持によるトリガー（押し込み瞬間）判定:
前フレームの入力状態（statePre_）と現在の状態（state_）の差分を比較することで、押しっぱなし（IsPush）だけでなく「押した瞬間（IsTrigger）」や「離した瞬間（IsRelease）」を正確に判定できるように設計しました。  

9. デバッグカメラ（DebugCamera）
3D空間上のモデル配置やアニメーション確認、および表示不具合の検証を迅速に行えるよう、独立した自由移動用デバッグカメラ機能（DebugCamera）を実装しました。

カメラ回転を考慮した直感的な移動制御:
キーボード操作（W/A/S/D/Space/Shift/矢印キー）による移動時、カメラの現在の回転行列（matRot）を乗算して移動ベクトルを変換（TransformNormal）しています。これにより、カメラがどの方向を向いていても「視線方向に対して前進・後退・横移動」が行える直感的な操作感を実現しました。  ワールド行列の逆行列によるビュー行列構築:
カメラ自体の位置・回転情報からカメラのワールド行列（worldMatrix）を作成し、その逆行列（Inverse(worldMatrix)）をビュー行列（viewMatrix_）として設定する正規の手順を忠実に適用しています。  ゲームカメラとのシームレスな切り替え機能:
TABキーなどをトリガーにして「通常のゲーム用カメラ」と「デバッグ用カメラ」を即座に切り替えられる構造（isDebugCameraフラグ制御）を用意し、開発作業・デバッグ作業の効率を大幅に向上させています。

10. 自作プレーヤーモデルおよび3Dモデル描画システム
DirectX 12の定数バッファやDescriptor Heapを活用し、複数メッシュ・複数マテリアルで構成されたプレーヤーモデル（player.obj等）を柔軟かつ高速に描画するパイプラインを構築しました

構造体による描画インスタンスの一元管理:
モデルデータ内の各メッシュに対して RenderMeshInstance 構造体を定義し、頂点バッファ・マテリアル・Transform・WVP（World/View/Projection）定数バッファおよびテクスチャ（SRV）を個別に管理しています。これにより、モデルの特定のパーツのみを非表示（visible）にしたり、部分ごとにライティングやテクスチャを割り当てたりする柔軟なカスタマイズを可能にしています。  ImGuiと連携したリアルタイム調整環境:
描画パラメータ（位置・回転・スケール、マテリアルカラー、ライティングモード [なし/Lambert/Half-Lambert]、UVトランスフォーム）をImGuiのGUI上からリアルタイムにパラメータ変更・確認できる構成としました。これにより、デザイナーや他のエンジニアがビルドし直すことなく視覚的確認を行えるように配慮しています。
